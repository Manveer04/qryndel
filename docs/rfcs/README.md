# Request For Comments

RFCs are used for major changes to UDL syntax, semantics, type behavior,
portability guarantees, or public APIs. Open an issue or pull request to
discuss the proposal before implementation.

An RFC should normally include:

- Summary
- Motivation
- Proposed design
- Examples
- Compatibility considerations
- Alternatives
- Open questions

The process is intentionally lightweight. The founding maintainer coordinates
decisions while the project is small, and community participation is welcome.
